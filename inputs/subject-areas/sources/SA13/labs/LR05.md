# LR05 Реализация контроля входных данных в заданном модуле

SA13 Сервис экспорта отчётов

Вы готовите решение для системы «Сервис экспорта отчётов» (OKFKS-SA13). Её критичная функция — формирование и выдача отчёта. Для освоения метода ниже используется отдельный учебный эпизод. Модуль регистрации заявок оборудования принимает объект без проверок. Из-за пустых полей, неверных кодов и недопустимых значений заявки попадают в очередь обработки и вызывают повторные ошибки. Нужно реализовать локальную функцию проверки и испытать её на выданном наборе без сетевых запросов. Перенос на вашу предметную область выполняется последним действием: необходимо объяснить последствие для конкретного актива, а не только заменить название системы.

Контроль входа проверяет контракт до побочного действия. Корректная реакция содержит понятную ошибку и не допускает постановки недопустимой заявки в очередь. Граница проверяется с обеих сторон.

Используйте фактор некорректного ввода из ЛР04. Выданный validateRequest — отдельный учебный модуль; его контракт нельзя менять под удобные тесты.

В ЛР06 передайте коды ошибок и правило блокировки недопустимого действия; в ЛР08 — события отказа в обработке без записи чувствительного входа. В ЛР20 повторите подход «ожидание до запуска».

## Контракт модуля

Вход: объект request

Выход: объект { ok: boolean, errors: string[] }

Safety: функция не изменяет входной объект, не читает файлы и не отправляет данные в сеть
